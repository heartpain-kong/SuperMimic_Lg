# 0.7.0：修复运动任务的静止奖励收入

用户提供的 `lg (4)` 显示：0.4 m/s 固定前进、1200 秒、1925 轮后正常保存，末轮速度误差 0.3866 m/s，前进奖励 0.0184（满值 0.5），总奖励仍有 3.2331。这能确认未跟上速度；不能仅凭世界模型归一化损失 0.0027 宣称策略有效，也不能据此确定世界模型梯度是唯一原因。

旧公式下，一个理想静止、正立、高度正确的合成样本得 3.38995 分。只计算速度/零转向/正立/高度四项就有约 3.0546 分。这个收入来自宽速度奖励和与运动进度无关的正向辅助奖励。

## 新公式

默认 `--motion-reward-mode progress`：

1. 运动指令下，速度与转向跟踪项减去同一指令下静止机器人的跟踪分。与目标同向的小速度仍有连续收益，反向运动得到更差的跟踪分。
2. 有符号进度支持前进、后退、横移和纯转向；平移与转向都被要求时取两者归一化进度的平均值。
3. 正立、高度、步态和抬脚的正向辅助收入乘以 `[0,1]` 的实际指令进度；保留门控梯度，机器人从静止开始动就有收益。倒置姿态的负分和现有动作/滑移/功率/关节/躯干惩罚保留。
4. 明确采样到零指令时，仍使用站立稳定奖励。物理失败条件、动作缩放、观测维度和模型结构不变。

修复后的同一理想静止样本，在运动指令下得 0 分。新旧奖励绝对分数不可直接比较。没有改变生产配置的网络、H32、actor 1 次、critic 20 次或 1200 秒训练预算；本轮不宣称新的吞吐提升。

`--motion-reward-mode legacy` 保留旧公式用于独立对照，12 个使用真实 XML 足端运动学的样本与 0.6.0 输出完全一致，输入/动作梯度最大差约 4.77e-7。公式选择进入共享任务配置和检查点契约，BPTT、HIM/PPO、CLI 与工作台使用同一规则。

## 诊断与物理评估

新增训练指标：

| 指标 | 含义 |
|---|---|
| `velocity_x_mps`, `velocity_y_mps`, `yaw_rate_rps` | 实际机身航向坐标系的平移速度与世界转向速度 |
| `wm_online_velocity_xy_rmse_mps` | 真实采集过程中，模型一步预测的平面速度向量 RMSE |
| `wm/velocity_xy_rmse_mps` | 世界模型拟合窗口内有效步的平面速度向量 RMSE |
| `policy/imagined_velocity_error_xy_mps` | 想象轨迹的速度指令误差 |

真实采集与想象轨迹的初始状态/噪声分布不同，不能把二者平均指标的差直接解释为严格配对的模型偏差。最终看无探索噪声的实际物理评估。

`evaluate_velocity --policy all` 对 XMimic 检查点评估 raw、EMA 和零动作，对普通 SuperMimic 评估 raw 和零动作。原有 auto/raw/ema 选项继续可用。新增 `assessment` 将进程正常退出与运动达标分开：每个种子都须完整存活、前进至少指令距离的 70%、速度误差不超过指令平均速度的 50%（最低阈值 0.05 m/s），且误差明显优于同种子零动作基线。零指令/纯转向不被此平面行走判定误标为达标，返回 `not_applicable`。

这些是短测条件，不是跨地形或真实机器人泛化保证。`needs_training` 是有效评估结果，CLI 正常退出；评估代码出错才是执行失败。旧日志的“失败 0”只是该轮采集步的统计。
